### 3. Ключ почтового провайдера

Пока их нет, регистрация по паролю **закрыта намеренно**: письмо подтверждения
не уходит, адрес не подтверждается, а расшаренный по почте мозг требует
подтверждённого адреса — то есть аккаунт получался тупиковым (см. `lib/auth.ts`).

Нужны `EMAIL_FROM` и `RESEND_API_KEY` в `.env`. Код проверяет их наличие через
`emailReady` в `lib/env.ts` и включает регистрацию сам.

Отправки написаны: `sendVerificationEmail` и `sendResetPassword` в
`lib/auth.ts` шлют через `lib/mail.ts` (Resend REST). Осталось только вписать
ключи и проверить на живом адресе.

Готово, когда новый аккаунт по паролю получает письмо, подтверждает адрес и
видит расшаренный ему мозг.

### 4. Ключи NOWPayments

`NOWPAYMENTS_API_KEY` и `NOWPAYMENTS_IPN_SECRET`. Без них страница баланса
показывает ручной путь «напишите нам», с ними — кнопки сумм и оплату криптой.

В личном кабинете NOWPayments указать IPN callback:
`https://mozg.sh/api/payments/nowpayments`.

Логика уже проверена без аккаунта: `npm run check:payments` (17 проверок —
подпись, повтор, промежуточные статусы, «в колбэке заявлено 999999»).

Готово, когда тестовое пополнение реально доходит до баланса, а `check:money`
после этого по-прежнему сходится.

## На разработчике

### 5. Наполнить каталог остальными разделами

Сейчас заняты `gamedev` (Stake Engine) и `ai` (MCP). Пусто: `web`, `backend`,
`mobile`, `data`, `devops`, `design`, `security`, `product`, `craft`.

Сидер обобщён — добавить раздел это **запись в массиве `PACKS`** в
`scripts/catalogue.ts`, не новый скрипт. Там уже лежит заготовка для Tailwind
v4 (`--only tailwind`, 197 страниц, не запускалась).

Два правила, выученных на MCP и записанных в комментариях того же файла:

- **Версии.** Если репозиторий держит рядом несколько выпусков (`2025-06-18`,
  `2026-07-28`, `draft`), брать только последний — иначе мозг противоречит сам
  себе на каждой детали. Флаг `versioned: true`, новейшая папка определяется
  сама.
- **Предложения — не спецификация.** У MCP 42 файла `seps` это proposals; мозг,
  который не отличает предложенное от принятого, хуже пустого. Такие пути в
  `skip`.

Что брать: то, чего модель **не знает или знает неверно** — вышло после
обучения, либо специфицировано настолько точно, что пересказ уже ошибка. Мозг
из документации, которую модель помнит наизусть, — это трата токенов.

```bash
npm run catalogue -- --owner egorfdrv@gmail.com --dry            # план
npm run catalogue -- --owner egorfdrv@gmail.com --only tailwind  # один пакет
```

Стоимость: примерно 4 цента за страницу.

Готово, когда в `/explore` в каждом разделе есть хотя бы один мозг с оценкой
выше 50%, и `npm run ask` на нём отвечает по делу.

Страница `docs/2026-07-28/tools/inspector/web.mdx` из документации MCP отклонена

Сейчас единственный выход — `npm run requeue --failed`, и она отклонится снова.
Нужен способ владельцу посмотреть замаскированные находки и сказать «это пример,
пропусти» — интерфейс их уже показывает, не хватает кнопки и флага на источнике.

Место: `src/lib/scan.ts`, `sources.findings`, страница мозга.

Готово, когда владелец может провести конкретный источник мимо сканера, и это
видно в интерфейсе как осознанное решение, а не как обход.

### 8. Тонкие заметки в RGS API — промпт исправлен, нужен перезалив

`systemPrompt` в `src/lib/extract.ts` теперь требует сохранять таблицы
параметров дословно, построчно («Never summarise a table into prose»). Но
промпт действует только на новые извлечения — существующие заметки не
изменились, и у источников закеширован `extract_payload`.

Чтобы фикс дошёл до мозга (`--reread` включает готовые источники и сбрасывает
кеш извлечения; стоит как обычный ингест):

```bash
npm run requeue -- --brain stake-engine-rgs-api --reread
npm run exam -- --brain stake-engine-rgs-api      # после того как воркер дочитал
npm run diagnose -- --brain stake-engine-rgs-api
```

Готово, когда `diagnose` перестал показывать «notes are the cap» для этого
мозга.

## Что не надо переделывать

Эти вещи выглядят как кандидаты на улучшение, но проверены и работают как
задумано. Прежде чем менять — прочитать комментарий рядом.

- **Реранкер не нужен.** `diagnose` научился отличать «судья видел и не
  засчитал» от «не нашлось». На RGS API это 7 против 2 — упирается в качество
  заметок, а не в ранжирование. Реранкер не изменил бы ничего.
- **Мозги не копируются покупателю.** Добавление кладёт строку в `library`,
  материал остаётся у автора и продолжает обновляться. Копия застыла бы в
  моменте покупки. Офлайн-снимок берётся экспортом.
- **Вложенность ровно одна.** Триггер в `0006_families.sql`. Два пути пишут
  мозги — форма и MCP, — и правило, которое соблюдает один, не правило.
- **Экзамен родителя ищет по семье.** Иначе оценка описывала бы 29 заметок,
  когда агент получает 694.
- **Цена родителя накрывает детей.** `lib/paywall.ts`. Иначе покупатель обходит
  родителя и берёт детей даром.
