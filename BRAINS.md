# BRAINS — какие мозги добавить и как их обучать

Анализ под две цели: **трафик** (бесплатные мозги-магниты, которые находятся
поиском и каталогами) и **продажи** (платные мозги, за которые реально платят).
Дата: 2026-08-04. Привязано к существующему пайплайну (`scripts/catalogue.ts`).

---

## 1. Главный принцип: платное ≠ репак публичных доков

Это самое важное решение во всём документе.

**Бесплатный мозг** — это публичная документация, которую модель знает плохо
(вышла после cutoff, меняется быстро, или «перефраз = баг»). Собирается
скриптом из GitHub-репо доков за час. Его ценность — *свежесть и точность*,
а не эксклюзив. Такой мозг продать нельзя: любой может собрать такой же,
и покупатель это понимает.

**Платный мозг** — это знание, которого **нет в публичном доступе**: рабочие
рецепты, грабли, числа из практики, «за что реально реджектят», внутренние
чеклисты. Его нельзя собрать краулером — его пишет эксперт. Ценность —
*эксклюзив и экономия времени/денег*.

Из этого следует стратегия каталога:

```
Бесплатные (8–12 шт)  →  SEO + каталоги + «попробуй как это работает»
       │                    ↓ трафик, регистрации, доверие к качеству
Платные (3–5 шт)      →  деньги. Продаются через 5 бесплатных запросов
                          из агента — продукт сам себя демонстрирует
```

Бесплатный каталог — это витрина качества. Человек видит, что бесплатный
Svelte-мозг отвечает идеально → верит, что платный Slot Studio за $29 стоит
своих денег. Поэтому бесплатные мозги должны быть **бездупречно обучены** —
это не халява для юзера, это твоя реклама.

## 2. Бесплатные мозги-магниты (трафик)

### Критерии отбора (по убыванию)

1. **Доки моложе cutoff модели или меняются каждый месяц** — иначе мозг не
   нужен, модель и так знает.
2. **«Перефраз = баг»** — точные имена полей, флаги, коды ошибок. Там, где
   важна дословность, мозг незаменим.
3. **Большая аудитория агент-кодеров** — прокси: npm downloads, GitHub stars.
4. **Доки живут в GitHub-репо как markdown** — тогда добавление = одна запись
   в `PACKS` в `scripts/catalogue.ts`, без нового кода.

### Готовый список (каждый — запись в PACKS)

Уже есть: Stake Engine, MCP, OWASP Cheat Sheets, OWASP ASVS, AI SDK, Expo,
Svelte 5, Tailwind v4. Добавить, в порядке приоритета:

| # | Мозг | Репо / источник | Почему сработает |
|---|---|---|---|
| 1 | **Next.js 15/16 + React 19** | `vercel/next.js` → `docs/` | Самая массовая связка. Модели галлюцинируют на App Router, Server Actions, кэшировании — оно менялось в каждой минорке |
| 2 | **Anthropic API + Claude Code** | `anthropics/anthropic-cookbook`, docs.anthropic.com (есть llms.txt) | Мета-попадание: пользователи mozg — это пользователи Claude. Мозг про инструмент, в котором они сидят прямо сейчас |
| 3 | **OpenAI API** | `openai/openai-cookbook` + platform docs | Responses API, Agents SDK — всё моложе cutoff, модели путают со старым Chat Completions |
| 4 | **Supabase** | `supabase/supabase` → `apps/docs/content/` | Огромная база, доки пухнут ежемесячно, Auth/RLS/Edge Functions — типичные места ошибок агентов |
| 5 | **Stripe API** | `stripe/openapi` (спека!) + stripe-docs | Ошибка агента в платежах стоит денег → ценность очевидна. OpenAPI-спека = идеальный материал («перефраз = баг» в чистом виде) |
| 6 | **Playwright** | `microsoft/playwright` → `docs/src/` | Агенты массово пишут тесты и путают API локаторов/фикстур |
| 7 | **Drizzle ORM** | `drizzle-team/drizzle-orm` → docs | Молодой, быстрорастущий, доки меняются каждый релиз |
| 8 | **Hono + tRPC** | `honojs/website`, `trpc/trpc` → `www/docs` | Хайповый стек ранних адоптеров = аудитория mozg 1:1 |
| 9 | **Cloudflare Workers** | `cloudflare/cloudflare-docs` → `src/content/docs/workers/` | Быстрорастущая платформа, Wrangler-конфиг меняется постоянно |
| 10 | **shadcn/ui** | `shadcn-ui/ui` → `apps/www/content/docs/` | Все генерят UI через агентов, CLI и registry-формат свежие |

**Ритм: один мозг в неделю, не больше.** Каждый новый мозг — это:
- новая SEO-страница `/b/mozg/{slug}` под запросы «X docs for claude code»,
  «X MCP server», «does claude know X»;
- повод для поста в X/Reddit («Claude keeps hallucinating Next.js caching,
  so I built it a brain — 94% on the exam»);
- свежесть каталога для возвращающихся.

Не делать 10 за выходные: полуобученный каталог — антиреклама.

### Что НЕ брать в бесплатные

- **Python, Django, React 18, классику** — модель знает их лучше, чем доки.
  Мозг получится бесполезный, и это будет видно на демо-вопросах.
- **Темы без репо с markdown-доками** — если доки только в рендеренном
  JS-сайте без llms.txt, стоимость сборки выше выгоды на старте.
- **Больше 2–3 мозгов на одну тему** — каннибализация SEO-страниц.

## 3. Платные мозги (продажи)

### Почему за них заплатят

Формула цены платного мозга: **(часы, которые он экономит) × (ставка
покупателя) × (эксклюзивность)**. Поэтому платные мозги строятся не вокруг
«больших» тем, а вокруг **дорогих ошибок в узких нишах с деньгами**.

### Портфель платных мозгов

| Мозг | Цена | Что внутри (почему эксклюзив) |
|---|---|---|
| **Slot Studio · Mechanics** (есть) | $29 | Механики слотов, чеклист аппрува «за что реально реджектят», математика — авторский опыт, не доки |
| **Slot Studio · Compliance** | $19–29 | Комплаенс stake.us/social casino, запрещённые термины, юрисдикции. Ошибка = недели переделок |
| **Smart Contract Auditor** | $49 | Паттерны уязвимостей с реальными эксплойтами, чеклисты аудита, «за что реджектят на audit». Аудитория привыкла платить $$$ за знания, $49 — копейки |
| **App Store / Google Play Review** | $19 | «За что реально реджектят» с кейсами, формулировки ответов ревьюерам, обход типичных отказов. Гайды Apple намеренно расплывчаты — практика есть только у тех, кто шиппит |
| **Quant / Exchange APIs** | $29–49 | Bybit/Binance/ccxt: реальные грабли (rate limits, rounding, funding, ликвидации), рабочие рецепты подписей и реконнектов |
| **Stripe в бою** (платный слой над бесплатным мозгом) | $19 | Не API-спека, а практика: webhooks идемпотентность, dunning, налоги, миграции подписок — то, чего в доках нет |

Важно: **начать с 3 платных максимум**, все — в нишах, где автор (ты) реально
эксперт или может привлечь эксперта. Платный мозг от не-эксперта видно на
пяти бесплатных запросах — и это убьёт доверие ко всему маркетплейсу.

### Механика продажи (уже встроена в продукт — использовать в полный рост)

1. **5 бесплатных запросов из агента** — главный продавец. Значит, первые
   ответы платного мозга должны быть ошеломляюще точными: на демо-вопросах
   покупатель решает за 2 минуты. Обучать мозг надо **с демо-вопросов
   покупателя**, а не по порядку доков.
2. **Anti-bluff метрика** на публичной странице («answers 27/30 ·
   anti-bluff 8/8») — единственное доказательство «мозг реально знает»,
   которое нельзя подделать маркетингом. Держать у всех платных 90%+.
3. **Бесплатный мозг-затравка из той же ниши.** Slot Studio продаётся через
   бесплатный Stake Engine: человек пришёл за доками → видит рядом платный
   «а вот ещё практика и чеклист аппрува». Та же пара нужна каждой платной
   нише: бесплатный OWASP → платный Auditor, бесплатный Stripe API →
   платный Stripe в бою.
4. **Дифф-экзамен при покупке** (уже сделано) — показывать его на странице
   мозга как «вот что вы получите».

## 4. Как обучать: пайплайн под каждый тип мозга

### 4.1 Бесплатный мозг из репо (1–2 часа работы)

Рецепт уже проверен Stake Engine-сидером: **читать репозиторий, из которого
собран сайт доков, а не сам сайт** (рендер — это JS-шелл со словом "Loading",
markdown-исходники несут API-спеки как данные).

Шаги:

1. **Запись в `PACKS`** (`scripts/catalogue.ts`): repo, prefix, endings,
   goal родителя. Добавление темы = данные, не новый скрипт.
2. **Goal писать от спеки, не от памяти.** Урок из mcp-spec: первая версия
   goal спрашивала про «lifecycle от initialize до shutdown», а протокол это
   убрал — экзамен честно заваливал мозг по ложной предпосылке. Экзамен
   ловит ошибки в самой цели. Правило: goal = что мозг должен уметь по
   *текущей* версии, без того, что «кажется, там было».
3. **Фильтровать мусор на входе** (`skip`, `versioned`):
   - changelog, archive, drafts, i18n-копии, legacy-версии — выкинуть;
   - если репо держит все версии рядом (Expo, MCP) — только новейшая,
     иначе мозг противоречит сам себе на каждой детали (это хуже, чем
     отсутствие мозга);
   - большие темы делить на детей (spec / build / cookbook), как MCP и
     AI SDK — монолит на 500 страниц ищет хуже, чем три сфокусированных.
4. **Прогнать сидер**: `npm run catalogue -- --owner egor@mozg.sh --only <key>`
   (сначала `--dry` — смотреть число страниц и раскладку по детям).
5. **Цикл экзамена до ≥ 85%**:
   - `npm run exam -- --brain <slug>` → смотреть, какие категории красные;
   - красная категория = недостающие источники → долить конкретные страницы
     (не «ещё доков вообще», а именно то, чего не хватает по строке
     «не хватает: …»);
   - если вопросы экзамена сами кривые (ложная предпосылка, как в mcp-spec) —
     править goal и регенерировать проверки, а не заливать данные под кривой
     вопрос.
6. **Написать 5–10 демо-вопросов** на публичную страницу — по ним посетитель
   судит качество. Вопросы = реальные боли («какой заголовок для кэша в
   Next 16?»), не «что такое Next.js».
7. **Anti-bluff проверки**: negative-чеки уже поддержаны (`checks.kind =
   negative`) — добавить минимум 5 на мозг. Мозг, который уверенно отвечает
   на вопрос вне своей темы, хуже мозга, который молчит.

### 4.2 Платный экспертный мозг (дни, не часы)

Краулер здесь не работает — материал в голове эксперта и в приватных
материалах. Источники наполнения:

1. **Скриншоты и файлы из реальных проектов** — drag-n-drop в дашборд,
   VLM-извлечение само превратит в заметки (промпт извлечения уже заточен
   под goal). Скриншоты переписок с саппортом, реджектов, дашбордов —
   это и есть эксклюзив.
2. **Собственные скиллы/инструкции** — у тебя уже есть десятки готовых
   `.agents/skills/*.md` по слотам (это готовые notes kind=rule/pitfall,
   заливать почти без обработки).
3. **Обратная запись агентов** (`brain_write`) — после запуска каждая
   сессия покупателей становится QA: агент флагает неверную заметку,
   пишет урок. Включить ревью-очередь и обрабатывать её раз в неделю —
   платный мозг должен **расти после продажи**, это оправдывает цену
   («покупаешь не файл, а живой мозг»).
4. **Search-gap harvest** (уже работает в maintenance): вопросы юзеров, на
   которые мозг не нашёл ответа, складываются в `gap_suggestions` — это
   готовый TODO-лист наполнения. Раз в неделю: открыть, долить, экзамен.
5. **Экзамен платного мозга — строже**: цель 90%+, negative-чеков 8–10,
   и ручная вычитка топ-20 заметок (у платного мозга каждая заметка —
   часть товара).

### 4.3 Регулярное обслуживание (без этого всё протухает)

- **Ре-инжест по расписанию**: бесплатные мозги привязаны к живым репо —
  раз в 2 недели гонять сидер повторно (он пропускает уже виденные URL,
  так что докачивает только новое). Кросс-экзамен версий (`exam_regressions`,
  тег «went stale») сам покажет, где мозг устарел.
- **Публичные мозги без оценки ≥ 70% не выпускать** — чеклист из LAUNCH.md.
- **Следить за релизами**: у каждого бесплатного мозга в goal зашита
  «текущая версия» — новый мажор фреймворка = повод для поста («мозг уже
  знает Next 16.3, модель — ещё нет») и для ре-инжеста.

## 5. План на 8 недель

```
Нед 1:  Next.js + React 19 (бесплатный). Довести до 85%+, демо-вопросы.
Нед 2:  Anthropic API / Claude Code (бесплатный). Пост в r/ClaudeAI.
Нед 3:  Slot Studio · Compliance ($19) — наполнение из своих материалов.
Нед 4:  Supabase (бесплатный). Show HN с каталогом из 10+ мозгов.
Нед 5:  Stripe API (бесплатный) + анонс пары «API бесплатно / практика $19».
Нед 6:  Smart Contract Auditor ($49) — если есть эксперт на ревью заметок.
Нед 7:  Playwright (бесплатный) + Product Hunt.
Нед 8:  Разбор: какие бесплатные дают регистрации (PostHog по UTM),
        какие платные пробуют через 5 free queries (таблица calls).
        Удвоить то, что сработало; заморозить остальное.
```

Ограничение ресурса: бесплатный мозг = ~2 часа + $1–3 на ингест (Batch API),
платный = 2–4 дня эксперта. Поэтому соотношение в плане 5:3, а не наоборот.

## 6. Как измерить, что сработало

| Сигнал | Где смотреть | Порог «работает» |
|---|---|---|
| Трафик на `/b/mozg/{slug}` из поиска | PostHog + sitemap в GSC | рост неделя к неделе после 3–4 мозгов |
| Регистрации с UTM конкретного мозга | PostHog | ≥ 20 регистраций на мозг за месяц |
| Демо-вопросы → подключение мозга | calls по brain_id | ≥ 10% посетителей страницы |
| 5 free queries исчерпаны → покупка | calls + purchases | ≥ 10% |
| Платный мозг растёт после продажи | notes с author=agent/human | ≥ 5 новых заметок/нед — значит, живой |

Если бесплатный мозг за месяц не привёл ни регистраций — не доливать в него,
тема выбрана неверно (скорее всего, модель её и так знает). Если платный
пробуют, но не покупают — проблема в первых 5 ответах или цене, не в трафике.
